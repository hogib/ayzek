# 02 · Weights, export and fixtures

Inference is hand-written, so the checkpoints are converted once, by Python,
into a flat format C++ can read with no dependency.

```bash
# from the ayzek root; tools/ is its own uv project, and tools/reference/ holds
# the model classes and conditioning the checkpoints were trained with
uv run --project tools python tools/export_models.py \
    --detector-dir CKPT_DIR --picker wave_n250.pt
```

It needs `data/demo/DEMI.mseed` for the fixtures, so run
`tools/make_demo_data.py` first (see `05-pipeline.md`).

The magnitude regressor's inputs come from seismic_cli's encoder, which needs
torchaudio, so its export runs in the data_downloader environment:

```bash
uv run --project tools python tools/export_magnitude.py \
    --partition P0.pth --partition P1.pth --partition P2.pth --dataset dataset_magreg_fdsn_10s
```

It writes `models/magnitude_p{0,1,2}.ayzw` and `data/fixtures/magnitude.ayzw`.
Both scripts share the writer in `tools/ayzw.py`.

## What it writes

| file | contents | source |
|---|---|---|
| `models/detector_s{42,43,44}.ayzw` | the 3-seed per-window 6 s CNN-BiLSTM-attention detector | `cnn_earthquake/trained_model_perwindow_6s` |
| `models/spicker.ayzw` | the `wave` arm of the sphase P/S picker | `sphase/runs/wave_n250.pt` |
| `models/bandpass.ayzw` | `butter(4, [1, 45] Hz)` as `b`, `a`, and `lfilter_zi` | scipy |
| `models/stations.csv` | code, lat, lon, elevation for every AFAD station | `istasyon_katalog.csv` |
| `data/fixtures/dsp.ayzw` | six real DEMI windows: raw, cleaned, standardised | scipy |
| `data/fixtures/detector.ayzw` | the same windows' inputs, per-seed logits, ensemble probability, and the intermediates of seed 42 | PyTorch |
| `data/fixtures/picker.ayzw` | two 60 s windows' inputs, logits and intermediates | PyTorch |

`models/` and `data/` are gitignored; everything in them is regenerated by the
two scripts.

## AYZW layout

Little-endian throughout.

```
"AYZW"  u32 version = 1  u32 count
count x {
    u16 name_len  name
    u8 dtype  (0 f32, 1 f64, 2 i64, 3 u8)
    u8 ndim   u32 dims[ndim]
    u64 nbytes  data
}
```

Every file carries a `__meta__` tensor: a JSON string holding the model type,
the preprocessing it expects, the source checkpoint path, and the first 16 hex
digits of that checkpoint's SHA-256. A weights file therefore says what it was
built from.

Tensor names are PyTorch's `state_dict` keys, unchanged, and each C++ layer
reads the names its PyTorch counterpart owns. A renamed or reshaped parameter
fails at load with the name and both shapes. It never produces plausible wrong
output.

## Fixtures and tests

- `test_dsp` runs the C++ conditioning on the raw windows and compares with
  scipy. It checks the cleaned signal to 1e-7 relative and the standardised
  float window to 1e-5.
- `test_models` checks the detector layer by layer: conv stack, BiLSTM,
  attention, pooled embedding, logit, then the ensemble probability. It checks
  the picker the same way: stem, pooling, BiLSTM, attention, logits and picks.
  A mismatch names the first layer that diverges.

Both exit 77, which Meson reports as skipped, when their fixtures are missing.
